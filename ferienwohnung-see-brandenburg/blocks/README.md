# Reusable blocks (`list_blocks` / `get_block`)

Site id 51, ferienwohnung-see-brandenburg.de. Snapshot 2026-09-24. All 10 blocks are language `de` and active.

A block is an HTML fragment stored once on the platform and expanded by the server wherever a page contains its placeholder. `blocks/<name>.html` holds the exact HTML returned by `get_block` (no trailing newline added; character counts match the `htmlLength` reported by `list_blocks`).

## Placeholder syntax

- Without parameters: `[[BLOCK:name]]`
- With parameters: `[[BLOCK:name,key=value,key2=value2]]` – inside the block HTML a parameter is referenced as `{{param.key}}`; a parameter that is not passed falls back to the declared default.
- Site variables (`{{phone}}`, `{{booking_u1}}`, `{{company_name}}` …, see `config/variables.md`) are resolved inside blocks the same way as in pages.
- Restore a block with `save_block` (name, title, description, parameters with defaults, html); the platform bumps the version on every save.

## Notes

- `buchungsleiste` is shown/hidden by the site footer script (`config/footer-scripts.html`), which watches the `[data-hero]` element; the page section that hosts the inquiry form needs the class `bar-pad` on phones.
- `unterkuenfte-karten` (version 3) and `unterkuenfte-vergleich` are the single source of truth for the accommodation facts shown on several pages; change numbers there, not in the pages.
- Reference counts come from the `referencedBy` field of `get_block` and are per page (target type `Page`).
